# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Код лежить у `gamepad-keys/` — усі команди нижче виконуються звідти.
Коментарі в коді й документація українською; тримайтесь цього.

## Що це

`GamepadKeys` — застосунок для macOS у рядку стану, який перетворює ввід з
геймпада на системні події клавіатури й миші. Головний сценарій — браузерні ігри,
які не вміють у Gamepad API. Не гра і не бібліотека: увесь сенс у тому, щоб
подія дійшла до **чужої** програми.

## Команди

```sh
make run        # зібрати → встановити в /Applications → запустити
make install    # без запуску
make app        # тільки бандл у .build (запускати звідти не можна, див. нижче)
make icon       # перемалювати іконку (Tools/make-icon.swift → iconutil)
make cert       # одноразово: сертифікат для стабільного підпису
make clean
```

`make test` запускає перевірки повторення (`Tests/RepeatTests.swift`) без надсилання
подій у систему. Для реального вводу перевірка — збірка плюс журнал `~/.config/gamepad-keys/log.txt`
(перезаписується при кожному запуску). Він містить стан дозволу, знайдені
контролери, кожне натискання й кожну надіслану подію — це основний інструмент
діагностики, читайте його замість того, щоб питати користувача.

Логи в unified log (`log show`) **не потрапляють** — не витрачайте на це час.

## Обмеження середовища

**Повного Xcode немає, лише Command Line Tools.** У SDK macOS 27 `@State` та
решта обгорток SwiftUI — це макроси, а плагіни до них ідуть тільки з Xcode.
Тому інтерфейс на AppKit. Не пропонуйте SwiftUI: воно не збереться.

## Дозвіл і підпис — головне джерело «нічого не працює»

`CGEvent.post` без дозволу «Універсальний доступ» **мовчки нічого не робить**,
без жодної помилки. Три правила:

1. Запускати можна **тільки** `/Applications/GamepadKeys.app`. TCC прив'язує
   дозвіл до шляху: копія в теці проєкту — для macOS інша програма. Тому
   `make app` кладе бандл у `.build`, а `run` завжди відкриває встановлену копію.
2. Підпис має бути сертифікатом, а не ad-hoc. Ad-hoc вимога — `cdhash H"…"`,
   тобто хеш бінарника, і вона змінюється при кожній збірці, скидаючи дозвіл.
   Після `make cert` вимога стає
   `identifier "com.local.gamepad-keys" and certificate leaf = H"…"` і переживає
   перезбірки. Перевірка: `codesign -d -r- /Applications/GamepadKeys.app`.
3. Якщо дозвіл усе ж злетів, його не «вмикають галочкою» — треба прибрати запис
   кнопкою `−` і додати наново. Це робить користувач, не ви.

## Архітектура

Потік даних в один бік:

```
GameController → Mapper → InputSender → KeySender / MouseSender → CGEvent
                   ↑                                                 ↓
                AppState ← вікно (MappingWindowController)      чужа програма
```

- **`AppState`** — уся змінна частина: конфіг, профілі, підключені контролери,
  режим перехоплення клавіші. Не `ObservableObject`; вікно підписується двома
  замиканнями: `onChange` (перебудувати) і `onActivity` (лише індикатори — це
  буває часто, і повна перебудова там завелика). Усе на головній черзі.
- **`Mapper`** — по одному на контролер. Вішає обробники на **всі** кнопки,
  навіть непризначені, інакше у вікні не було б видно, яка кнопка натиснута.
- **`Slot`** — що саме можна призначити: кнопка або напрямок стіка.
- **`Action`** — у що: клавіша (`KeyCombo`) або кнопка миші. У конфігу рядком,
  миша з префіксом `mouse:`.
- **`InputSender`** ховає від `Mapper` різницю між клавіатурою і мишею.

### Речі, які легко зламати назад

- `GCController.shouldMonitorBackgroundEvents = true` в `AppState.init` —
  **обов'язково**. Без цього macOS віддає ввід тільки застосунку на передньому
  плані, а цей живе в рядку стану і не отримує нічого.
- `MouseSender` шле `mouseEventDeltaX/Y` разом із позицією. Браузерні ігри з
  Pointer Lock читають `movementX/movementY` саме звідти.
- Курсор рухає власний таймер на 120 Гц, а не події стіка: швидкість не повинна
  залежати від частоти оновлень контролера. Дробові частки пікселя переносяться
  на наступний кадр, інакше повільний рух округлюється до нуля.
- Стіки в режимі клавіш мають гістерезис (поріг виходу 0.7 від входу). Без нього
  стік на межі мертвої зони сипле down/up десятки разів на секунду.
- `KeySender.isPaused` вмикається на час перехоплення клавіші. Інакше кнопка
  геймпада надішле синтетичну подію, і монітор запише її як «призначення».
- `KeySender` рахує натискання на кожну клавішу: дві кнопки на одну клавішу не
  повинні відпускати її передчасно.
- Коди клавіш — **позиції**, не символи. `w` — фізичне місце W на US-розкладці.

## Конфіг

`~/.config/gamepad-keys/config.json`, пишеться при кожній зміні. Профілі
ідентифікуються **назвою** (`Profile.id` — обчислювана властивість, у JSON не
потрапляє). Усі поля читаються через `decodeIfPresent`, а `init(from:)` лежить в
`extension` — інакше Swift прибрав би memberwise-ініціалізатор. `Config.init(from:)`
підхоплює старий формат без профілів і загортає його в один профіль.

Редагуючи конфіг ззовні, спершу зупиніть застосунок (`pkill -x GamepadKeys`),
інакше він перезапише файл.

## Дрібниця з Makefile

Коментар у кінці рядка з `:=` потрапляє у значення змінної разом із пробілами.
Тримайте коментарі окремими рядками.
