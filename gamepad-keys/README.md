# gamepad-keys

Системний мапінг кнопок геймпада на клавіші клавіатури для macOS.
Живе в рядку стану, нативно на Apple Silicon, без kext, без Rosetta, без Xcode.

## Збірка

```sh
make app        # зібрати GamepadKeys.app
make install    # зібрати і покласти в /Applications
make run        # зібрати і запустити
```

Потрібні лише Command Line Tools (`xcode-select --install`).
Інтерфейс на AppKit саме тому: у SDK macOS 27 обгортки SwiftUI (`@State` тощо)
стали макросами, а плагіни до них ідуть тільки з повним Xcode.

## Перший запуск

1. Іконка геймпада з'явиться в рядку стану. Заповнена — контролер підключений.
2. Програма попросить дозвіл **Системні налаштування → Конфіденційність і
   безпека → Універсальний доступ**. Без нього клавіші не надсилаються;
   у вікні буде помаранчева смуга з кнопкою.
3. Меню → **Розкладка…** — вікно призначень.

> **Дозвіл прив'язаний до підпису й шляху бандла.** Ad-hoc підпис змінюється
> при кожній збірці, тому після кожного `make install` дозвіл треба видавати
> наново: виділити GamepadKeys у списку, **−**, потім **+** і вибрати
> `/Applications/GamepadKeys.app`.
>
> Щоб позбутися цього назавжди — один раз виконайте `make cert`. Вона створює
> самопідписаний сертифікат, підпис стає стабільним, і дозвіл переживає
> перезбірки. Команда запитає пароль від зв'язки ключів.
>
> З тієї ж причини запускати треба тільки копію з `/Applications`: копія в іншому
> місці — це для macOS інша програма з окремим дозволом.

## Повторення при утриманні

Галочка **«Повторювати при утриманні»** над списком кнопок вмикає повтор
для поточного профілю: приблизно 10 подій на секунду, доки призначення затиснене.
Клавіші надсилають повторні `keydown` з ознакою `repeat`, кнопки миші —
повторні кліки. Це також стосується напрямків стіка в режимі клавіш;
рух курсора залишається безперервним.

Після відпускання, зміни профілю або початку запису нового призначення повтор
зупиняється. Налаштування зберігається у профілі як `repeatEnabled`;
за замовчуванням і для старих конфігів воно вимкнене.

## Перевірки

`make test` компілює й запускає `Tests/RepeatTests.swift` без додаткових бібліотек.
Перевіряються збереження налаштування, повтор клавіш і кліків, модифікатори,
спільне призначення миші та зупинка повтору. Події перехоплюються до надсилання
в систему; користувацький конфіг і журнал не змінюються.
Для перевірки реального вводу використовуйте встановлений застосунок,
геймпад і `test-keys.html` у браузері.

## Як призначати

У вікні кожен рядок — одна кнопка або один напрямок стіка.

- **Зелена крапка** зліва загорається, коли ви тримаєте цю кнопку на геймпаді.
  Так найшвидше зрозуміти, який рядок вам потрібен.
- Натисніть кнопку з клавішею → напис зміниться на «натисніть клавішу…» →
  тисніть будь-яку клавішу на клавіатурі. Комбінації (`cmd+shift+a`) і
  самі модифікатори (`shift`) теж ловляться.
- **×** праворуч прибирає призначення.
- **Мертва зона** — наскільки треба відхилити стік, щоб він почав діяти.
- Кнопка **⌄** праворуч призначає кнопку миші. Окремим меню, а не
  «натисніть для запису», бо саме мишею ви й клацаєте по цьому вікну.

### Стік як миша

У заголовку секції стіка є перемикач **клавіші / миша**. У режимі миші стік
рухає курсор: чотири напрямки зникають, натомість з'являється **швидкість
курсора** (пікселів за секунду при повному відхиленні).

Швидкість наростає квадратично: біля центру курсор повзе — так можна цілитись,
— а до краю розганяється до повної. Мертву зону тут варто тримати малою (0.10–0.15),
інакше повільне прицілювання неможливе.

Разом із рухом надсилаються поля `mouseEventDeltaX/Y`, тому працюють і браузерні
ігри із захопленням курсора (Pointer Lock), які читають `movementX/movementY`,
а не позицію.

Поки вікно чекає на клавішу, вихід тимчасово вимкнений — інакше кнопка геймпада
надіслала б синтетичну клавішу і програма перехопила б власну ж подію.

## Діагностика

Внизу вікна — журнал: підключення контролерів, кожна натиснута кнопка, кожна
надіслана клавіша. **Копіювати** кладе його в буфер, **Тест клавіші** надсилає
`space` без участі геймпада — так видно, чи проблема в дозволі, чи в контролері.

Той самий журнал пишеться у файл: `~/.config/gamepad-keys/log.txt`
(перезаписується при кожному запуску).

Рядок стану підключення під шапкою має три стани:

| Колір | Що означає |
|---|---|
| сірий | контролера немає |
| помаранчевий | підключений, але жодної події ще не було |
| зелений | події надходять |

Якщо контролер підключений, а GameController його не бачить, у журнал
потрапляє список HID-пристроїв із VID:PID — видно, чи система бачить пристрій
узагалі, чи справа в непідтримуваній моделі.

## Профілі

Випадний список угорі — перемикання. Поле поруч — перейменування (Enter).
**+** створює копію поточного, **−** видаляє. Перемикати можна і з меню в рядку стану.

## Конфіг

`~/.config/gamepad-keys/config.json` — пишеться автоматично при кожній зміні,
але його можна редагувати й руками:

```json
{
  "activeProfile" : "Основний",
  "profiles" : [
    {
      "name" : "Основний",
      "buttons" : { "a" : "space", "lt" : "shift", "rb" : "cmd+w" },
      "leftStick" : { "up" : "w", "down" : "s", "left" : "a", "right" : "d",
                      "deadzone" : 0.5 },
      "rightStick" : null
    }
  ]
}
```

Старий формат без профілів читається і перетворюється автоматично.

### Назви кнопок

`a` `b` `x` `y` · `lb` `rb` `lt` `rt` · `up` `down` `left` `right` (хрестовина) ·
`menu` `options` `home` · `l3` `r3` (натиснення стіків)

На DualSense: `a` = Хрестик, `b` = Кружечок, `x` = Квадрат, `y` = Трикутник.
`home` (кнопка PS) може перехоплюватись самою macOS — перевірте по індикатору.

### Назви клавіш

Літери `a`–`z`, цифри `0`–`9`, `f1`–`f12`, стрілки `up` `down` `left` `right`,
`space` `return` `tab` `escape` `backspace` `delete` `home` `end` `pageup` `pagedown`,
`minus` `equal` `leftbracket` `rightbracket` `backslash` `semicolon` `quote`
`comma` `period` `slash` `grave`, модифікатори `shift` `ctrl` `alt` `cmd`
(та `rshift` `rctrl` `ralt`). Комбінації через `+`.

Повний список — у `Sources/GamepadKeys/KeyCombo.swift`.

### Кнопки миші

`mouse:left`, `mouse:right`, `mouse:middle` — пишуться в те саме поле, що й клавіші:

```json
"buttons" : { "r3" : "mouse:left", "l3" : "f" }
```

> Коди клавіш — це **позиції** на клавіатурі, а не символи. `w` — це фізичне
> місце W на US-розкладці; при українській розкладці воно дасть «ц».
> Ігри читають саме позицію, тож зазвичай це те, що потрібно.

## Іконка

Малюється кодом — `Tools/make-icon.swift`, `make icon`. У репозиторії немає
бінарних PNG: вигляд задається кількома числами на початку скрипта (колір
градієнта, символ, поля, радіус скруглення), а `iconutil` збирає з них `.icns`.

Оскільки програма живе в рядку стану (`LSUIElement`), у Dock її іконки немає —
вона видно у Finder та в списку «Універсальний доступ».

## Автозапуск

Меню в рядку стану → **Запускати при вході**. Працює через `SMAppService`,
тобто тільки для зібраного `.app` (не для `swift run`).

## Структура

| Файл | Відповідальність |
|---|---|
| `main.swift` | точка входу, режим «живе в рядку стану» |
| `AppDelegate.swift` | іконка й меню в рядку стану, вікно |
| `MappingWindowController.swift` | вікно розкладки |
| `SlotRowView.swift` | один рядок: індикатор, підпис, клавіша |
| `AppState.swift` | стан програми, профілі, підключення контролерів |
| `Config.swift` | читання/запис JSON, міграція старого формату |
| `Slot.swift` | що саме можна призначити і як воно підписується |
| `Mapper.swift` | прив'язка кнопок і стіків до дій |
| `Action.swift` | дія: клавіша або кнопка миші |
| `KeyCombo.swift` | розбір `"cmd+shift+a"` → код клавіші + модифікатори |
| `KeyCapture.swift` | перехоплення натискання з клавіатури при призначенні |
| `InputSender.swift` | один вхід для клавіатури й миші |
| `KeySender.swift` | системні події клавіатури |
| `MouseSender.swift` | рух курсора і кнопки миші |
| `HIDScan.swift` | діагностика, коли GameController не бачить контролер |
| `Log.swift` | журнал у вікні та у файлі |
| `Tools/make-icon.swift` | генератор іконки застосунку |
